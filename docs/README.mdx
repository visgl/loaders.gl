## Overview

loaders.gl is a collection of composable TypeScript modules for loading, scanning, transforming, and
writing data in JavaScript applications. It covers tabular, geospatial, imagery, and 3D formats with
consistent APIs for complete results, streamed batches, workers, and remote sources.

The modules are framework agnostic. Use them with any JavaScript application, or combine them with
[vis.gl frameworks](https://vis.gl/frameworks) such as [**deck.gl**](https://deck.gl) when loaded
data should be visualized.

## Code Examples

loaders.gl provides a small core API module with common functions to load and save data, 
and a range of optional modules that provide loaders and writers for specific file formats.

A minimal example using the `load` function and the `CSVLoader` to load a CSV formatted table into a JavaScript array:

```typescript
import {load} from '@loaders.gl/core';
import {CSVLoader} from '@loaders.gl/csv';

const data = await load('data.csv', CSVLoader);

for (const row of data) {
  console.log(JSON.stringify(row)); // => '{header1: value1, header2: value2}'
}
```

Streaming parsing is available using ES2018 async iterators, e.g. allowing "larger than memory" files to be incrementally processed:

```typescript
import {loadInBatches} from '@loaders.gl/core';
import {CSVLoader} from '@loaders.gl/csv';

for await (const batch of await loadInBatches('data.csv', CSVLoader)) {
  if (batch.batchType === 'data') {
    for (const row of batch.data) {
      console.log(JSON.stringify(row)); // => '{header1: value1, header2: value2}'
    }
  }
}
```

To quickly get up to speed on how the loaders.gl API works, see [Get Started](/docs/developer-guide/get-started).

## Design Goals

| Goal | What it means in practice |
| --- | --- |
| Framework agnostic | Return documented objects, typed arrays, tables, and batches that any JavaScript framework can consume. |
| Browser and Node.js | Keep the same core APIs usable in browsers, services, scripts, and tests. |
| Worker-ready parsing | Move expensive decoders to prebuilt workers when a module provides them. |
| Loader categories | Normalize related formats into shared application-facing data shapes. |
| Format autodetection | Select loaders from extensions, MIME types, and initial bytes when the input allows it. |
| Streaming | Process async input and parsed batches incrementally, including inputs larger than memory. |
| Composable bundles | Publish independent modules and lazy runtimes so applications can install what they use. |
| Binary-first data | Preserve compact typed-array and Arrow representations without adding WebGL dependencies. |
| Multi-asset loading | Resolve linked buffers, images, tiles, and texture levels through one loading path. |
| Modern JavaScript | Use TypeScript, ECMAScript modules, `ArrayBuffer`, and async iterators as portable primitives. |
