Overview​

loaders.gl is a collection of composable TypeScript modules for loading, scanning, transforming, and writing data in JavaScript applications. It covers tabular, geospatial, imagery, and 3D formats with consistent APIs for complete results, streamed batches, workers, and remote sources.

The modules are framework agnostic. Use them with any JavaScript application, or combine them with vis.gl frameworks such as deck.gl when loaded data should be visualized.

Loaders​

loaders.gl provides a wide selection of loaders organized into categories:

CategoryLoaders
Table LoadersStreaming tabular loaders for CSV, JSON, Parquet, Arrow, and loaders that can return Arrow tables with shape: 'arrow-table'
Geospatial LoadersLoaders for formats such as GeoJSON, KML, WKT/WKB, and Mapbox Vector Tiles.
Image LoadersLoaders for images and image utilities such as the parsed image API and binary image API.
Texture LoadersLoaders for compressed textures, Basis textures, and manifest-driven texture loaders for arrays, cubemaps, and mip chains.
Pointcloud and Mesh LoadersLoaders for point cloud and simple mesh formats such as Draco, LAS, PCD, PLY, OBJ, and Terrain.
Scenegraph LoadersglTF and OpenUSD loaders
Tiled Data LoadersLoaders for tiled 3D data such as 3D Tiles, I3S, and Potree.

Code Examples​

loaders.gl provides a small core API module with common functions to load and save data, and a range of optional modules that provide loaders and writers for specific file formats.

A minimal example using the load function and the CSVLoader to load a CSV formatted table into a JavaScript array:

import {load} from '@loaders.gl/core';
import {CSVLoader} from '@loaders.gl/csv';

const data = await load('data.csv', CSVLoader);

for (const row of data) {
  console.log(JSON.stringify(row)); // => '{header1: value1, header2: value2}'
}

Streaming parsing is available using ES2018 async iterators, e.g. allowing "larger than memory" files to be incrementally processed:

import {loadInBatches} from '@loaders.gl/core';
import {CSVLoader} from '@loaders.gl/csv';

for await (const batch of await loadInBatches('data.csv', CSVLoader)) {
  if (batch.batchType === 'data') {
    for (const row of batch.data) {
      console.log(JSON.stringify(row)); // => '{header1: value1, header2: value2}'
    }
  }
}

To quickly get up to speed on how the loaders.gl API works, see Get Started.

Design Goals​

GoalWhat it means in practice
Framework agnosticReturn documented objects, typed arrays, tables, and batches that any JavaScript framework can consume.
Browser and Node.jsKeep the same core APIs usable in browsers, services, scripts, and tests.
Worker-ready parsingMove expensive decoders to prebuilt workers when a module provides them.
Loader categoriesNormalize related formats into shared application-facing data shapes.
Format autodetectionSelect loaders from extensions, MIME types, and initial bytes when the input allows it.
StreamingProcess async input and parsed batches incrementally, including inputs larger than memory.
Composable bundlesPublish independent modules and lazy runtimes so applications can install what they use.
Binary-first dataPreserve compact typed-array and Arrow representations without adding WebGL dependencies.
Multi-asset loadingResolve linked buffers, images, tiles, and texture levels through one loading path.
Modern JavaScriptUse TypeScript, ECMAScript modules, ArrayBuffer, and async iterators as portable primitives.

Credits and Attributions​

loaders.gl is maintained by a group of organizations collaborating through open governance under the OpenJS and Linux Foundations.

While loaders.gl contains substantial amounts of original code, it also repackages lots of superb work done by others in the open source community. We try to be as explicit as we can about the origins and attributions of each piece of code, both in the documentation page for each module and in the preservation of comments relating to authorship and contributions inside forked source code.

Even so, we can make mistakes, and we may not have the full history of the code we are reusing. If you think that we have missed something, or that we could do better in regard to attribution, please let us know.
