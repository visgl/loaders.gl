Querying tables

Use query() when you need one Arrow table, or queryInBatches() to process Arrow batches as results arrive. Both execute the same logical query: filter source rows, select and rename columns, then apply a global limit. Import them from the optional @loaders.gl/core/query entry point.

Run your first query​

A URL requires an explicit source loader. This lets the format choose useful reads without making core depend on format implementations.

import {query} from '@loaders.gl/core/query';
import {ParquetLoader} from '@loaders.gl/tables/parquet';

const result = await query(
  {
    select: ['name', {column: 'population', as: 'people'}],
    where: {op: '>', args: [{property: 'population'}, 100000]},
    limit: 20
  },
  {source: 'https://example.com/cities.parquet', loaders: ParquetLoader}
);

console.log(result.numRows);
console.log(result.getChild('people'));

The result is an Apache Arrow Table. You can also pass an already loaded Apache Arrow table or an existing table scan source as source. Those inputs do not need loaders. Parser-only loaders such as ParquetLoader are not source loaders; use ParquetLoader for URL queries.

Keep logical operations in the first argument. Put source, loaders, signal, completion observers, and ordinary request/format options in the second:

const options = {
  source: 'https://example.com/cities.parquet',
  loaders: ParquetLoader,
  core: {fetch: authenticatedFetch},
  parquet: {batchSize: 1024}
};

See authentication for request credentials.

Describe the rows and columns​

Query fieldMeaning
selectOrdered column names or {column, as} aliases. Omit it to select every column.
whereA predicate over source column names, evaluated before aliases.
limitMaximum matching rows across the entire execution, including all batches.
fromOptional registered source name or {source, table} reference.

A predicate column need not appear in select. For example, selecting only name while filtering population retains population internally until filtering is complete. An output alias such as people does not become a WHERE property.

Predicates support comparisons, and, or, not, membership, and null checks. Use {op: 'isNull', args: [{property: 'population'}]} to find nulls. Comparisons with null produce an unknown result; WHERE retains only true results, so negating a comparison still excludes nulls. See the predicate reference for the full vocabulary.

Rows retain source order. A limit counts matches after filtering; it is not a sample or a sort. limit: 0 returns the projected schema without calling the source's result reader, although schema discovery can still read metadata. Empty results retain field names, types, nullability, and available metadata. An explicit empty select list, unknown columns, duplicate output names, and invalid limits are errors.

Stream results​

Change the function, not the query:

import {queryInBatches} from '@loaders.gl/core/query';

for await (const batch of queryInBatches(
  {select: ['name'], where: {op: '>', args: [{property: 'population'}, 100000]}},
  {source: 'https://example.com/cities.parquet', loaders: ParquetLoader}
)) {
  await consume(batch);
}

The iterator starts work when consumed and requests input as the consumer advances. break closes the upstream iterator. An empty execution yields one empty schema-bearing batch.

query() retains the complete result. Streaming can bound executor working memory by the input batch size, but batches you retain still occupy memory. Arrow projection and rename reuse column buffers; slices can retain their original buffers, and scattered filtering can allocate new ones.

Progressive aggregate snapshots​

queryProgressive() streams complete replacement tables for aggregate views. Replace the previous table on every yield. Each result covers all input rows processed so far.

import {queryProgressive} from '@loaders.gl/core/query';

for await (const {table, rowsProcessed, final} of queryProgressive(
  {
    groupBy: 'country',
    where: {op: '>', args: [{property: 'temperature'}, 30]},
    aggregates: [
      {function: 'count', as: 'samples'},
      {function: 'avg', column: 'temperature', as: 'average'}
    ]
  },
  {source, emitEveryBatches: 8}
)) {
  updateVisualization(table);
  if (final) console.log('Finished', rowsProcessed);
}

Pass a structured groupBy and aggregates request. Supported reductions are COUNT, SUM, AVG, MIN, and MAX. Filtering runs first. Group keys may be finite numbers, strings, booleans, or null and appear in first-seen order. COUNT(column) and numeric reductions skip nulls. An empty numeric reduction returns null. Counts use safe integers, and aggregate columns use Float64.

State grows with the number of groups and aggregates. rowsProcessed counts filtered rows. The iterator always emits a final snapshot, including for empty inputs, and closes the source on early return. Use emitEveryBatches to control how often it rebuilds the output.

For pure Arrow RecordBatch streams, set queryOutput: 'snapshots' on queryInBatches(aggregateQuery, options) and replace the prior result on every yield. Regular queries yield append-only Arrow RecordBatch objects by default. Use queryProgressive() for explicit rowsProcessed and final metadata.

Reuse and name sources​

Create a source once when you want repeated queries. Give it an explicit name when it will be referenced by from:

import {createDataSource} from '@loaders.gl/core';

const cities = await createDataSource('cities.parquet', ParquetLoader, {
  core: {name: 'cities'}
});

try {
  const result = await query(
    {from: 'cities', select: ['name'], limit: 20},
    {sources: [cities]}
  );
} finally {
  await cities.close();
}

source.name is fixed at creation. Defaults come from an already available data name or schema name, then a File/URL basename without its last extension, then an explicit source type or source. Naming does not fetch data. core.name overrides the default; it does not rename table columns. Registered names must be unique; unknown and duplicate names fail explicitly.

Without from, the query uses options.source. Supplying sources alone does not select a default. With from, the selected registered source takes precedence over options.source.

Select a table inside a source​

Some sources expose several tables through getTable(name). Keep the outer source name and loaded table name separate:

import {GeoPackageSource} from '@loaders.gl/geospatial/geopackage';

const warehouse = await load('world.gpkg', GeoPackageSource, {
  core: {name: 'warehouse'}
});

const result = await query(
  {from: {source: 'warehouse', table: 'cities'}, select: ['name']},
  {sources: [warehouse]}
);

Only the selected table is resolved. It must return an Apache Arrow table or a source supporting table metadata and reads. Raster, tile, or catalog sources are not automatically converted into tables. Names are matched exactly. A string such as from: 'warehouse.cities' is one literal source name; use the structured form for qualified lookup.

Use SQL through an injected parser​

Pass the optional parser explicitly. Math.gl’s parseSQLQuery() supports SELECT projections, AS aliases, optional FROM, WHERE, and LIMIT.

import {parseSQLQuery} from '@loaders.gl/core/query/sql';

const result = await query('SELECT name FROM warehouse.cities LIMIT 20', {
  sources: [warehouse],
  sqlParser: parseSQLQuery
});

You can also pass a parser promise:

const sqlParser = import('@loaders.gl/core/query/sql').then(module => module.parseSQLQuery);

ESM imports are tree-shakeable: importing just the parser removes Arrow execution code from the bundle. For a smaller parser without built-in WHERE support, use parseSQLSelect() from the same subpath. It accepts SELECT, AS, FROM, LIMIT, and OFFSET. Pass a parseWhere callback to enable WHERE.

These are deliberately partial parsers. They preserve identifier case, accept double-quoted names and doubled-quote escapes, and require AS for column aliases. They reject comments, table aliases, qualified column references, joins, sorting, grouping, and multiple statements. Quote literal column names containing dots. Input length, token count, and nesting are bounded.

An application can still supply its own SQLQueryParser to translate supported syntax into the logical query. The function may return that query asynchronously. Parsers are invoked only for SQL string input. A dynamic import starts when its promise is created; use an async parser function if the import itself should wait until SQL is used.

Omitting SQL FROM uses options.source. Preserve quoted identifiers as separate components: FROM "warehouse.v2"."cities.v3" maps to {source: 'warehouse.v2', table: 'cities.v3'}. Core validates the returned query and source capabilities before executing it.

Explore sources and schemas​

The same query APIs return Arrow tables for metadata commands:

import {parseSQLQuery, createSQLCatalog} from '@loaders.gl/core/query/sql';

const options = {sources: [warehouse], sqlParser: parseSQLQuery};
const sources = await query('SHOW SOURCES;', options);
const tables = await query('SHOW TABLES FROM warehouse;', options);
const columns = await query('DESCRIBE warehouse.cities;', options);

SHOW SOURCES lists registered names without I/O. SHOW TABLES lists all discoverable tables in source registration order; add FROM to inspect one source. DESCRIBE reports fields in schema order, including their Arrow type, nullability, and JSON field metadata. Use DESCRIBE cities for a single-table source. Collections require a qualified table name, even if they expose a default table. Empty results retain the command's output schema.

Table listings include a safely quoted table_reference and a queryable flag. The flag indicates support for the common table query contract, not whether a backend has its own SQL API. Discovery never calls read() or getTable(). A provider may still access headers, schema samples, a complete container file, or a remote metadata service; cancellation requires its cooperation. Sources remain caller-owned.

For a schema explorer, use the lazy model directly and pass its structured reference to query():

const catalog = createSQLCatalog([warehouse]);
const registered = catalog.getSources(); // local names only
const discovered = await catalog.getTables('warehouse');
for (const table of discovered) {
  const schema = await catalog.getSchema(table.reference);
  // Render schema.fields; use table.reference as a query's from value.
}

Multi-table providers expose getTablesMetadata() and, for lazy per-table schemas, getTableMetadata(name). Single-table sources reuse getQueryMetadata(). Tables without a metadata discovery contract cannot be listed; requesting an unavailable schema fails explicitly. See the API reference for result columns and provider interfaces.

Cancel work and observe completion​

Pass an AbortSignal to cancel cooperative source discovery and execution. Completion is reported once per public query, including source-opening failures, cancellation, limits, and consumer return.

const controller = new AbortController();
const result = await query({select: ['name']}, {
  source: 'https://example.com/cities.parquet',
  loaders: ParquetLoader,
  signal: controller.signal,
  onQueryComplete: summary => console.log(summary.status, summary.rowsReturned)
});
// From a cancellation handler: controller.abort();

A throwing observer does not change the result. rowsRead describes batches received by the query, not physical rows skipped by storage pruning; use source telemetry for bytes and row-group metrics.

URL-created sources are closed by the query. Sources supplied as objects, registered in sources, or returned by their getTable() remain caller/provider-owned; close their owning source when it is no longer needed. Iterator cleanup still runs on early return and errors.

Understand format limits​

CSV, NDJSON, Arrow IPC, and Parquet table sources share these semantics, but their physical work differs. Sequential text/IPC projection happens after decoding. Parquet can skip columns and prune row groups, then applies exact filtering before the result limit. Streaming does not guarantee fewer downloaded bytes for every format.

CSV blanks are empty strings, not SQL nulls. NDJSON inference examines its first decoded batch; provide ndjson.schema when that batch cannot determine a field type or when you need precise types. Changing the output schema, including nullability, during execution is an error. Metadata can only be preserved when the format supplies it.

These entry points currently support selection, aliases, predicates, and limits. They do not add joins, sorting, aggregates, or synchronous execution. For exact signatures, errors, capability details, and benchmark commands, see the query API reference.

Injected SQL parser contract​

An injected sqlParser returns a portable logical query. Use parseSQLQuery from @math.gl/sql/parser for SELECT expressions, ARRAY projections, casts, computed WHERE expressions, and catalog commands. Math.gl compiles expressions against each source schema. Loaders.gl requests the referenced columns and evaluates computed filters before applying LIMIT. Sources can still push down portable column predicates. Unsupported expressions fail with a terminal query error.

Typed SELECT output​

Use CAST to set the physical type of a result column. The type is fixed even when the result contains no rows or the selected values are all null.

SELECT CAST(longitude AS FLOAT64) AS longitude,
       CAST(temperature AS FLOAT32) AS temperature,
       CAST(confidence AS FLOAT16) AS confidence
FROM readings

DOUBLE PRECISION and REAL are aliases for FLOAT64 and FLOAT32. Integer targets are INT8, UINT8, INT16, UINT16, INT32, UINT32, INT64, and UINT64. The 64-bit integer columns use JavaScript bigint values. Out-of-range casts raise an error.

The structured form uses the same cast plan. The output name defaults to the source column name.

const result = await query({
  select: [
    {column: 'longitude', cast: 'float64'},
    {column: 'temperature', cast: 'float32'},
    {column: 'confidence', cast: 'float16'}
  ]
}, {source});

CSV and NDJSON can write simple float casts on decoded float columns directly into their output Arrow buffers. Other casts and queries with filters use the portable Arrow evaluator. Casts run after filtering and the row window. The loader's input schema still controls how it decodes the original values. FLOAT16 expressions require a runtime with native Float16Array support.

Grouped SQL scans​

Use queryGroupedSQL from @loaders.gl/core/query to return the final grouped table from a URL, table scan source, or Arrow table. The scan accumulates each group across input batches. For example:

const totals = await queryGroupedSQL(
  'SELECT hex, SUM(count) AS visits FROM data GROUP BY hex',
  {source: url, loaders: [CSVLoader]}
);

Select one grouping column first, followed by named COUNT, SUM, AVG, MIN, or MAX aggregates. An optional WHERE filters rows before grouping. Use queryProgressive when intermediate replacement snapshots are needed.
