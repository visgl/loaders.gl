Core module

@loaders.gl/core

The public loaders.gl API for loading, parsing, streaming, and encoding data across format modules. Common utilities are available through dedicated subpaths such as core/schema, core/loader-utils, and core/worker-utils.

Get started ↗Using loaders ↗Core API reference ↗

The loader boundary

Formats change. The application path can stay the same.

Choose a loader explicitly when the format is known, or let the selector choose from a compatible set. The result remains the shape your application is built to consume.

The core module

One small API around many format modules.

Core handles fetching, parser selection, loading, streaming, encoding, and saving. Format packages remain optional, so an application can compose only the paths it needs.

01

Fetch

Resolve URLs, files, streams, and request options

02

Select

Choose explicit loaders or detect among candidates

03

Process

Load complete results or iterate through batches

04

Write

Encode and save compatible application data

@loaders.gl/core coordinates format loaders and writers. Pass explicit loaders to keep format selection and return types local to your application.

TaskAPIs and guidance
Fetch and parseload, loadInBatches
Parse loaded dataparse, parseSync, parseInBatches
Prepare metadata loaderspreload and preloadSync
Select a loaderselectLoader and selectLoaderSync
Open a runtime sourcecreateDataSource, or async load for lazy source loaders
Fetch bytesfetchFile, or the runtime's fetch
Encode dataencode, encodeText, and synchronous/batched variants
Adapt streamsmakeIterator and makeStream
Configure shared defaultssetLoaderOptions and getLoaderOptions

registerLoaders remains a deprecated compatibility API. Core does not export save or writeFile; save encoded bytes with your platform's filesystem, download, or upload API.

Detailed guide

Core APIs and lightweight entry points

The reference below lists the parser, fetch, loader-selection, encoding, writing, and micro-loader APIs.

Micro-Loaders​

Loaders with limited functionality but with minimal bundle size impact:

LoaderDescription
JSONLoaderA minimal non-streaming JSON loader that uses the built-in JSON.parse function
NullLoaderA loader-object that ignores input data and always returns null.

Utility subpaths​

Reusable scan, geometry construction, geometry processing, and codec APIs are available through independent subpaths:

ImportUtilities
@loaders.gl/core/constantsBranch, repository URL, and worker tag constants.
@loaders.gl/core/loader-utilsLoader contracts, streams, file systems, and source utilities.
@loaders.gl/core/worker-utilsWorker pools, messaging, and transfer helpers.
@loaders.gl/core/schemaShared schemas, table and geometry types.
@loaders.gl/core/schema-utilsSchema conversion, table helpers, and Arrow transport.
@loaders.gl/core/polyfillsIndependent Node platform adapters.
@loaders.gl/core/scanScan planning and execution, Arrow queries, portable predicates, and format-neutral source wrappers.
@loaders.gl/core/arrow-geometryGeometry builders and loader-facing conversion helpers.
@loaders.gl/core/geoarrowGeoArrow inspection, validation, conversion, coordinate operations, clustering, and spatial indexes.
@loaders.gl/core/wktGeometry codec helpers; TWKB is also available from @loaders.gl/core/wkt/twkb.

Import these APIs through their subpaths. The core root entrypoint keeps its existing exports. Format loader and writer descriptors remain in their format modules, including @loaders.gl/geospatial/wkt; database adapters remain in @loaders.gl/sql.

import {createScanEngine, parseSQLPredicate} from '@loaders.gl/core/scan';
import {GeoArrowBuilder} from '@loaders.gl/core/arrow-geometry';
import {inspectGeoArrowVector} from '@loaders.gl/core/geoarrow';
import {convertWKTToGeometry} from '@loaders.gl/core/wkt';
