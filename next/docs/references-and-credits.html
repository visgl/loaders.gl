References and credits

loaders.gl brings together work by many people: original loaders and integration code, carefully adapted parsers, independently maintained codecs, open specifications, and sample data generously shared for testing and examples. We thank the authors and communities who make this possible. Their work deserves recognition wherever it continues to be used, including after a dependency is removed, a parser is rewritten, or packages are consolidated.

This page credits implementation, ideas, technical advice, standards and data as separate contributions. The package inventories below identify retained source and applicable notices. An algorithm reference or a compatible API does not by itself mean that an upstream implementation was copied.

Tables, streaming parsers and scientific arrays​

  • Matthew Holt and PapaParse contributors developed PapaParse, the foundation of the adapted CSV parser. loaders.gl's streaming and table interfaces build on that work; they do not replace its authorship. The source records the original 5.0.0-beta.0 fork.
  • Nuno Job, Isaac Z. Schlueter and Clarinet contributors supplied Clarinet, the streaming JSON parser retained with its BSD notice. This parser supports incremental processing of large JSON and GeoJSON documents.
  • ironSource and the parquetjs/parquets contributors supplied the original parquetjs and parquets implementation. Hyperparam contributors supplied hyparquet delta-decoder adaptations. Kyle Barron and parquet-wasm contributors supply the optional parquet-wasm backend. The parquet-go project inspired earlier documentation; that reference is separate from the JavaScript parser's MIT license.
  • Apache Arrow contributors develop the columnar memory format, IPC format and Arrow JavaScript implementation that make cross-library table exchange possible. Some Arrow-like type definitions were adapted from ArrowJS and retain Apache-2.0 terms. Paul Taylor at Graphistry provided extensive technical advice for loaders.gl's Arrow integration.
  • Kyle Barron’s GeoArrow work inspired loaders.gl’s GeoArrow integration and its geospatial Arrow conversion and processing APIs. We thank Kyle for helping establish these foundations.
  • MongoDB's js-bson contributors and SheetJS contributors supply the optional BSON and spreadsheet implementations. Wrapping these libraries is a distinct contribution from implementing their codecs.
  • cheminfo/netcdfjs contributors supplied the adapted NetCDF parser. Michaël Zasso and IOBuffer contributors supplied the binary buffer reader used by that parser.
  • Trevor Manz and zarrita.js contributors, Gerrit Zuidhof and zarr.js contributors, and the Zarr and OME communities supply zarrita.js, zarr.js, and the array and multiscale conventions used by the scientific sources.
  • Isaac Z. Schlueter and sax-js contributors, through Maxim Mazurok's sax-ts TypeScript fork, supplied the retained SAX parser. Natural Intelligence and fast-xml-parser contributors supply the alternate XML implementation.

Geospatial formats, vector tiles and terrain​

  • Vladimir Agafonkin and Mapbox contributors supplied vector-tile-js, geojson-vt, and earcut. These implementations underpin retained MVT decoding, vector tiling and triangulation code. Anand Thakker's vt-pbf supplied adapted vector-tile writing.
  • Björn Harrtell and FlatGeobuf contributors supplied the adapted FlatGeobuf reader. Its BSD-2-Clause notice remains with the retained code.
  • Christian Schwarz's wkx supplied geometry serialization lineage, including retained TWKB code. Mapbox's wellknown supplied historical WKT parsing. Current WKT/WKB/CRS codecs use math.gl; moving or replacing implementations does not erase the provenance of code that remains.
  • Brandon Liu and the Protomaps community develop PMTiles. MapLibre contributors develop MapLibre Tile. Their separately installed readers supply the corresponding tile integrations.
  • Fabian Schindler and geotiff.js contributors supply geotiff.js, used for compatibility decoding alongside loaders.gl's numeric TIFF core. Esri's LERC contributors supply LERC raster compression implementations.
  • Vladimir Agafonkin's MARTINI and Michael Fogleman and Vladimir Agafonkin's Delatin supply terrain mesh reconstruction. HERE Europe B.V. supplied the quantized-mesh-decoder implementation adapted for quantized terrain.
  • SQL.js and SQLite contributors supply the database implementation used by GeoPackage adapters. DuckDB contributors supply the independently installed database runtimes used by SQL sources.

Meshes, point clouds and 3D tiles​

  • Ricardo Cabello (mrdoob) and the three.js community supplied the OBJ parser foundation. Wei Meng supplied the PLY loader foundation; Filipe Caixeta and Mugen87 are credited in the adapted PCD loader. We retain these individual credits alongside the three.js MIT notice.
  • Uday Verma and Howard Butler's Plasio supplied the LAS/LAZ parser lineage. Hobu and laz-perf contributors, laz-rs contributors, and Martin Isenburg, rapidlasso and LASzip contributors developed important LAZ implementations and algorithms. The embedded laz-rs-wasm manifest also credits Thomas Montaigu and Chris Lee. Backend choices and newer TypeScript work are described separately from retained adaptations.
  • Markus Schütz and Potree contributors supplied the Potree point-cloud loader lineage. Connor Manning's copc.js informed the original COPC module. Its current primary reader is implemented in loaders.gl.
  • CesiumJS contributors and the Cesium engineering team supplied adapted 3D Tiles utilities and collaborated on the original integration. Cesium-derived tileset traversal, collection and bounding-volume helpers retain Apache-2.0 provenance even where their interfaces have changed.
  • Esri and its engineering collaborators publish I3S and LEPCC specifications and reference implementations. Esri funded and contributed the tile-converter development effort. The current I3S integration and converters also represent substantial original loaders.gl work.
  • Benjamin Wasty's gltf-loader-ts supplied adapted glTF schema types. Arseny Kapoulkine and meshoptimizer contributors supply the vendored meshopt decoder. Google Draco contributors supply geometry compression implementations and the Web IDL underlying the adapted Draco types.

Images, textures, compression and archives​

  • Karl Cheng's binary-gltf-utils supplied binary-image inspection and data-URI decoding foundations. Sindre Sorhus and file-type contributors supplied adapted ISO BMFF detection code.
  • Tarek Sherif's PicoGL supplied compressed-texture parsing foundations. Binomial and Basis Universal contributors supply the encoder/transcoder used by Basis and KTX2 integrations. The checked-in runtime inventories record pinned versions and checksums.
  • Tim van Scherpenzeel's texture-compressor supplies the application-installed command-line tool used by the compressed texture writer. The retained Crunch runtime carries a Zlib SPDX identifier; the attribution audit records the unresolved historical provenance.
  • Arjun Barrett's fflate supplies retained DEFLATE/GZIP/ZLIB code. Pierre Curto supplied the adapted LZ4 implementation. Google’s retained JavaScript Brotli decoder is credited separately from optional Brotli backends. The compression adapters also thank the maintainers of compress-utils, Brotli, fzstd, hysnappy, lz4js, pako, snappyjs and zstd-codec for independently maintained codecs.
  • T. Jameson Little's tar-js supplied retained TAR construction helpers. Historical ZIP loaders wrapped JSZip; the current archives implementation uses loaders.gl's archive and compression APIs.
  • Yahoo's gifshot contributors, Anthony Dekker (NeuQuant), Kevin Weiner (Java implementation), and Thibault Imbert (the ActionScript version) are credited in the retained GIF encoding source.
  • Axel Rauschmayer's async-iter-demo and Vsevolod Strukchinsky's require-from-string supplied small but valuable utility foundations retained in the core package.

Utility foundations​

  • Brian Todd Button supplied md5-wasm, the foundation of the retained MD5 implementation and adapter. jsdom’s abab contributors supplied the base64 decoding foundation. wqli78’s CRC32 gist is cited in source as inspiration.
  • Gozala supplied historical web-file and web-blob polyfills. GitHub’s fetch contributors supplied the Headers polyfill; Anthum, Inc. supplied fetch-progress-indicators. BTOdell supplied path-resolve, and Jesse Tane supplied hex-transcoder.
  • Joshua Bell and text-encoding contributors, and the WHATWG Encoding Standard community, supplied encoding algorithms, polyfill code and encoding indexes. The package inventory distinguishes the public-domain dedication from the standard-derived material.
  • derhuerst and parse-gml-polygon contributors supplied GML polygon parsing. taketwo’s three-pcd-loader supplied the separate LZF decompressor lineage. Kepler.gl contributors supplied indexed tilestats attribute handling.

Specifications and research​

We thank the people who design, document and maintain interoperable formats: Khronos (glTF and KTX), OGC (including 3D Tiles, GeoPackage and service standards), Esri (I3S and ArcGIS), ASPRS (LAS), the Apache Arrow, Parquet and ORC communities, GeoArrow and GeoParquet contributors, STAC contributors, Zarr and OME-NGFF communities, WMO (GRIB), CF metadata contributors, Pixar and the OpenUSD community, and the Chrome Trace Event and Perfetto communities.

Specifications, research publications, implementation source, and conformance fixtures are separate contributions. Format documentation links the applicable standards and papers. Supporting a format does not imply certification or that the standards organization's reference implementation is bundled. math.gl supplies many shared spatial algorithms; its own references and credits identify the underlying mathematical and implementation lineage.

Maintaining provenance​

When adding or updating an adaptation:

  1. Preserve upstream authors, copyright headers, full licenses and applicable NOTICE files. Record the source URL, version or commit, and material changes.
  2. Update the owning package's notice index and this page. Historical ports with unknown versions should say so; a current upstream release is not evidence of the version originally copied.
  3. Include the notices and license texts in published packages and retain them when redistributing generated bundles and workers.
  4. Credit datasets separately, including the asset creator, source, version, license and transformations; record checksums for pinned binary assets.
  5. Run yarn check-attributions, inspect package contents, and build the website. The check catches missing indexes, broken local notice links and omitted package files; it cannot determine whether attribution is historically complete.

If a credit is incomplete or incorrect, please open an issue with the source or history we should consult. We welcome corrections and fuller acknowledgements.
